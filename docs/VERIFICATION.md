# Luma 1.2 verification

Verification environment: Flutter 3.35.6 / Dart 3.9.2, 10 September 2026. Demo captures use fictional records only.

## Automated checks

- Static analysis passes with no issues.
- A standard Android debug APK builds successfully for version 1.2.0+3; this is separate from the integration-test application.
- All 41 portable tests pass: 14 accounting/import tests, 6 calendar-statistics tests, 1 drill-down filter test, 2 statistics UI tests and 18 responsive layout configurations.
- Layout coverage: 375×812 portrait, 844×390 landscape and 768×1024 tablet; light/dark; text scaling 1.0×, 2.0× and 3.2×; reduced motion. Core navigation, reports, budgets, entry, onboarding, settings, import/export, wallets and schedules are covered.
- Statistics checks cover previous calendar periods, leap years, partial-period cutoffs, future exclusion, missing baselines, cash-flow semantics, and year → month → day navigation. UI regression coverage switches periods after scrolling so expansion state cannot collide with a saved scroll position.
- Native integration exercises actual SQLite storage, import deduplication, ledger isolation, transfers, recurring posting, rollback, backup restore and reopening; transaction entry, quick income, filters and statistics drill-down.

## Native and visual checks

The full native integration suite passes on an Android API 33 emulator, iPhone 16 Pro (iOS 18.5) simulator and iPad Pro 11-inch M4 (iOS 18.5) simulator. Phone/tablet layouts, report breakdowns, light/dark appearance and enlarged type are supplied to a fresh Impeccable finish reviewer. The fresh Impeccable reviewer returned **ship**, with no material fixes within those 13 native captures and sampled source. See `DESIGN_REVIEW.md` for the exact scope and evidence limitations. Captures are generated by `integration_test/app_test.dart` through `test_driver/integration_test.dart`; the application itself renders the pixels in a native simulator/emulator, with no web recreation.

## Limits

No database migration is required. Personal financial data, signing credentials and test databases are excluded from the repository. Physical device testing, TalkBack/VoiceOver exploration and app-store publication have not been performed. Native simulator tests do not establish release signing or store readiness. The repository contains no release signing identity; existing release users need an update signed with their original key.

Version 1.2.0 uses build number 3. Historical version 1.1 release notes remain in `REDESIGN.md` and do not certify a version 1.2 release package.
